🏗️ Provider 架构流程图

详细解析 Aether 的多 Provider 抽象层设计

📋 架构概述

核心思想：Provider 层是一个抽象层，用于统一不同 AI 服务商（OpenRouter、Anthropic、OpenAI）的接口。 通过这个抽象层，上层代码（API Route）无需关心具体使用哪个服务商，只需要调用统一的接口即可。

🔄 完整请求流程

1
前端发起请求

用户在聊天界面发送消息，前端调用 POST /api/chat

2
API Route 接收请求

解析请求参数：conversationHistory, model, backend, tools, systemInstruction

3
获取 Provider 实例

getProvider(backend) 根据 backend 参数返回对应的 Provider（openrouter/anthropic/openai）

4
初始化 Provider

provider.initialize(config, context) 传入模型配置、工具列表、对话历史等

5
创建辅助工具

StreamController（SSE 流控制）、ResearchTracker（工具调用追踪）、ToolExecutor（工具执行器）

6
进入迭代循环（最多 20 次）

每次迭代：调用 provider.runIteration() → 执行工具 → provider.appendToolResults()

7
流式返回结果

通过 SSE 实时推送 content、thinking、tool_call、tool_result 等事件到前端

🔌 IProvider 接口定义

interface IProvider { readonly name: Backend; // "openrouter" | "anthropic" | "openai" // 初始化：传入配置和上下文 initialize(config: ProviderConfig, context: ProviderContext): void; // 运行一次迭代：返回异步生成器，yield 流事件，return 迭代结果 runIteration(): AsyncGenerator<StreamEvent, IterationResult, undefined>; // 追加工具执行结果，用于下一次迭代 appendToolResults(results: ToolCallResult[]): void; // 检查是否支持某个模型 supportsModel(model: string): boolean; }

📦 核心数据类型

ProviderConfig

配置信息：

  • model: 模型名称
  • tools: 可用工具列表
  • searchEnabled: 是否启用搜索
  • systemInstruction: 系统提示词

ProviderContext

执行上下文：

  • conversationHistory: 对话历史
  • conversationId: 会话 ID
  • logger: 日志记录器
  • onProgress: 进度回调

StreamEvent

流事件类型：

  • content: 文本内容
  • thinking: 思考过程
  • tool_call: 工具调用
  • tool_result: 工具结果
  • error: 错误信息

IterationResult

迭代结果：

  • shouldContinue: 是否继续迭代
  • pendingToolCalls: 待执行的工具
  • assistantText: 助手回复文本

🎯 Provider 实现细节

1 BaseProvider（抽象基类）

  • 存储 config 和 context
  • 提供 initialize() 方法，调用子类的 onInitialize() 钩子
  • 提供 ensureInitialized() 检查是否已初始化
  • 子类必须实现 runIteration() 和 appendToolResults()
⬇️

2 AnthropicProvider（具体实现）

  • onInitialize(): 构建系统提示词，转换消息格式为 Anthropic 格式
  • runIteration(): 调用 streamAnthropicCompletion()，解析流式响应
  • 处理流事件: text → content, thinking → thinking, tool_use → tool_call
  • 返回结果: 如果有工具调用，返回 shouldContinue=true；否则 false
  • appendToolResults(): 将工具结果追加到消息历史，格式化为 Anthropic 的 tool_result
⬇️

3 OpenRouterProvider / OpenAIProvider

  • 类似的实现模式，但适配各自的 API 格式
  • OpenRouter 支持多种模型，OpenAI 使用标准 OpenAI API
  • 消息格式转换、工具调用格式都有所不同

🔁 迭代循环详解

const maxIterations = 20; let iteration = 0; while (iteration < maxIterations) { iteration++; // 1. 运行一次迭代，获取流式事件 const generator = provider.runIteration(); let result; while (true) { const { done, value } = await generator.next(); if (done) { result = value; // IterationResult break; } streamController.send(value); // 发送 StreamEvent 到前端 researchTracker.handle(value); // 追踪工具调用 } // 2. 检查是否需要继续 if (!result.shouldContinue) { break; // 没有工具调用，结束循环 } // 3. 执行工具调用 const toolResults = await toolExecutor.execute(result.pendingToolCalls); // 4. 将工具结果追加到 Provider，准备下一次迭代 provider.appendToolResults(toolResults); }
为什么需要迭代？

因为 AI 模型可能需要多次调用工具才能完成任务。例如：

  • 第 1 次迭代：模型决定搜索 "Next.js 最新版本"
  • 第 2 次迭代：根据搜索结果，模型决定访问官网获取详细信息
  • 第 3 次迭代：模型整合信息，给出最终回答

🛠️ 辅助工具类

StreamController

负责将 StreamEvent 转换为 SSE 格式并发送到前端

streamController.send({ type: "content", content: "Hello" }); // 输出: data: {"type":"content","content":"Hello"}\n\n

ResearchTracker

追踪工具调用状态，用于前端显示工具执行进度

researchTracker.handle({ type: "tool_call", tool: "brave_search", args: { query: "..." } });

ToolExecutor

执行工具调用，返回结果。支持 brave_search、fetch_url、render_html 等

const results = await toolExecutor.execute([ { id: "1", name: "fetch_url", args: {...} } ]);

✨ 抽象层的优势

🔄 统一接口

API Route 只需要调用 provider.runIteration()，无需关心底层是 Anthropic 还是 OpenAI

🧩 易于扩展

添加新的 AI 服务商只需实现 IProvider 接口，无需修改上层代码

🎯 职责分离

Provider 负责与 AI 服务商通信，ToolExecutor 负责工具执行，StreamController 负责流控制

🧪 易于测试

可以轻松 mock Provider 进行单元测试，不依赖真实的 AI 服务

🎓 总结

Provider 层的本质：

它是一个适配器模式的实现，将不同 AI 服务商的 API 统一成相同的接口。

通过 initialize() → runIteration() → appendToolResults() 的循环，实现了工具调用的完整流程。

上层代码（API Route）只需要关心"发起请求 → 处理流事件 → 执行工具 → 返回结果"，而不需要关心底层使用的是哪个 AI 服务。
